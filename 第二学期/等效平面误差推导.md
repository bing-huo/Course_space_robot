# 等效平面误差推导

> 解决的问题：测速系统性偏低 10~11%，且两套算法、两个速度下比值一致。
> 结论：不是算法、不是时间、不是板，而是**标定面与跟踪面不在同一高度**。

## 一、现象

| 工况 | 设定速度 | v1 实测 | v2 实测 | 比值（v2/设定） |
|---|---|---|---|---|
| 第一段 | 21 cm/s | 18.79 | 18.95 | **0.902** |
| 第二段 | 30 cm/s | 27.23 | 26.67 | **0.889** |

两个不同速度、两套算法，比值都落在 **0.886~0.902**——是**乘性系统偏差**，不是随机噪声。

## 二、先排除三类原因

### 2.1 算法

V2.2（固定门限）与 V2.3（自适应门限 + αβ + 稳态窗）在两段**接近匀速**的参考录像上
速度差 **≤2%**（21 cm/s：+0.9%；30 cm/s：−2.1%）。
→ 分析选择不是主因。（V2.1 无门限版受阴影影响、不稳定，不参与此项对比；
第一学期的 `CV/main.py` 用手机视频 + 180×60 标定，也没在这批桁架视频上跑过；
非匀速段的估计方法差异会更大，见 [`算法改进说明.md`](算法改进说明.md)。）

### 2.2 时间基准

视频按 60 fps 写入，实测采集约 61 fps → 时间轴约长 1.7%，速度被低估 1.7%。
→ 量级不够，排除。

### 2.3 标定板打印与 H

- 板在 A/A2/B2 三张图里映射出的边长都是 **1.50 cm**，H 自洽；
- 手推 30 cm 验证给出 27.55 与 28.45 两次，彼此差 3%，是**测距方法本身的误差**；
- 几何上：镜头 143 cm − 桁架顶面 26 cm ≈ 117 cm，板反推 WD = 113.5 cm，差约 3%。

→ 板/尺度最多贡献百分之几，不足以解释 10%。

## 三、推导

设：

- 标定面（板所在平面）到镜头距离 `WD_c = 113.5 cm`；
- 目标实际被跟踪的可见结构所在平面到镜头距离 `WD_t`；
- 两者高度差 `Δh = WD_t − WD_c`（目标平面在标定面下方）。

**同一段物理位移** `d_t` 在目标平面上，投影到像素的位移是

```
p = d_t · f / WD_t        （f = 焦距对应的像素尺度）
```

而用标定面的 H 去解释这段像素位移时，会算成

```
d_meas = p · WD_c / f = d_t · (WD_c / WD_t)
```

所以比值

```
r = d_meas / d_t = WD_c / WD_t
```

已知 `r ≈ 0.886`，`WD_c = 113.5 cm`：

```
WD_t = WD_c / r = 113.5 / 0.886 = 128.1 cm
Δh  = WD_t − WD_c = 14.6 cm
```

**桁架高度 14 cm。** 推导值与独立测量的桁架高度吻合（差 0.6 cm）。

**物理原因**：桁架是镂空结构，俯视时穿过顶面开口能看到**底部框架**；
可见白色质量的等效平面因此接近底部，而不是标定板所在的顶面。

## 四、补偿与验证

```
PLANE_SCALE = WD_t / WD_c = 1 / r = (113.5 + 14.0) / 113.5 = 1.1233
```

把世界坐标乘上这个系数后：

| 目标 | 补偿前 | 补偿后 | 误差 |
|---|---|---|---|
| 21 cm/s | 18.95 | **20.92** | **−0.4%** |
| 30 cm/s | 26.67 | **29.28** | **−2.4%** |

两段同时对上。注意：这里只用了一个参数（Δh），却同时改善了两种速度——
如果模型错了，不可能两个速度同时收敛。

## 五、通用规则

### 5.1 公式

```
Δh = WD_c · (1/r − 1)
PLANE_SCALE = (WD_c + Δh) / WD_c
```

其中 `r = 实测速度 / 设定速度`（假定设定值可信）。

### 5.2 什么时候要重推

- **换目标**（高度、结构、是否镂空）→ 重推；
- **把标定板直接垫到等效平面** → `Δh = 0`，不需要修正；
- **换机位/换镜头/改高度** → 先重标 H，再按新 `WD_c` 重推；
- **目标从"镂空桁架"换成"实心平板"** → 等效平面会抬到板面，`Δh` 接近 0。

### 5.3 怎么确定等效平面（三种办法，按可靠性排序）

1. **直接标定在等效平面**：把板垫到目标可见结构的重心高度，重标 H（最干净，`Δh=0`）；
2. **用两段已知速度反推**：本文的方法，需要假定目标速度可信；
3. **几何估计**：镂空目标取"可见结构面积的加权高度"，实心平板取板面。

## 六、误差预算（修正后）

| 来源 | 量级 | 状态 |
|---|---|---|
| **等效平面（本项）** | **−11.4%** | ✅ 已补偿（×1.1233） |
| 视频时间基准（60 vs 61 fps） | +1.7% | ⬜ 可用实测 fps 补 |
| 标定板打印/尺度 | ≤2%（由两段残差反推） | ⬜ 钢尺可定 |
| 算法差异（v1 vs v2） | <1.5% | ✅ 已收敛 |
| 小车实际速度 | ≤2.4%（推断） | 已包含在残差里 |

## 七、报告里怎么写

> 标定板置于桁架顶面，俯视时可见白色结构以底部框架为主，导致跟踪等效平面比标定面低约
> 14 cm；按 `Δh = WD_c(1/r − 1)` 反推得到 14.6 cm，与桁架实测高度 14 cm 一致。
> 补偿后 21 cm/s 与 30 cm/s 的测量误差分别为 −0.4% 与 −2.4%。

这样写的好处：**误差来源可解释、参数可独立核验、补偿只用一个物理量**，
而不是拿目标速度硬凑一个系数。
