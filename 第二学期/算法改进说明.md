# 第二学期算法改进说明（第一版 → 第二版）

> 对照对象：**第二学期自己的两版分析/测速工具**
> · 第一版 `tools/analyze_run.py`
> · 第二版 `tools/measure_speed.py`（v2）
>
> 跨学期（第一/二/三学期）的算法比较见根目录 [`04_算法比较.md`](../04_算法比较.md)。
> 本文件只回答一个问题：**在同一个检测内核上，把后处理换掉，结果变不变、值不值。**

## 一、两版的关系

检测内核完全一样：**MOG2 背景差分 → 形态学 → 单轮廓 → 图像矩质心 → 单应 H → Alpha-Beta**。
区别只在"怎么取前景、怎么估速度、怎么统计"这三层。

| | 第一版（analyze_run） | 第二版（measure_speed） |
|---|---|---|
| 亮度门限 | 固定 `gray ≥ 100` | **自适应**：中位 + 0.5×(P95−中位) |
| 阴影处理 | 依赖 MOG2 的 127，深阴影会混进前景 | 在门限里直接排除深阴影 |
| 速度估计 | 逐帧差分后做全局线性拟合 | **Alpha-Beta**（α=0.15, β=0.005） |
| 稳态窗 | 无（按面积过滤后全段拟合） | **自动选取**：偏差 ≤15% 且连续 ≥1.0 s |
| 平面修正 | 无 | **PLANE_SCALE = 1.1233** |
| 逐帧日志 | 无 | 有（`--log`） |
| 用途 | 当晚快速看数 | 正式测量 |

## 二、第二版的框架（重点）

```
相机帧 ─► FrameClock(硬件时间戳)
       ─► 灰度
       ─► MOG2 前景 ──┐
       ─► 自适应亮度门限 ──► 前景 = 运动 ∧ 够亮
       ─► 形态学(开/闭)
       ─► 单目标门控(面积范围 + 离预测位置最近)
       ─► 轮廓质心(图像矩)
       ─► 单应 H（含等效平面修正 PLANE_SCALE）
       ─► Alpha-Beta
       ─► 自动稳态窗
       ─► 速度 / 轨迹 / 逐帧日志
```

四块改动各自的理由：

1. **自适应亮度门限**：单侧强光把影子投得很黑，MOG2 的 `detectShadows` 判不出，影子会并进前景，
   质心被拖偏。同一段视频：**无门限 18.0 cm/s，加固定门限 24.0 cm/s**。
   写死常数在 L0/L4 会失效，所以第二版改用画面自身的分位数。

   > ⚠️ **口径澄清**：表中"第一版"**已经带固定门限**，所以它受阴影影响不大。
   > 那个 18.0 cm/s 是**加门限之前**的版本，不是第一版。三档对比：
   >
   > | 版本 | 门限 | 同一段 `truss_15s.mp4` |
   > |---|---|---|
   > | 加门限前 | 无 | 18.0 cm/s（影子并进前景，质心被拖） |
   > | 第一版 | 固定 100 | 24.0 cm/s（阴影基本排除） |
   > | 第二版 | 自适应 | 与第一版同级；换 L0/L4 不用改常数 |
   >
   > 所以"两版差 ≤2%"与"阴影影响 33%"并不矛盾：**两版都已经排除了阴影**，
   > 差别只在门限是否自适应、平滑方式和窗口选取。
2. **Alpha-Beta**：逐帧差分的速度噪声大（P90 比中位高 7%），滤波后平稳；参数少、可解释。
3. **自动稳态窗**：判据来自测量协议（15% / 1.0 s），不靠人工截取，换速度也自动适配。
4. **逐帧日志**：指标 2（检测失败率）的唯一数据来源。

## 三、实测对比（同一批录像，10 ms / F2.8 / 6 dB）

| 指标 | 第一版 | 第二版 | 变化 |
|---|---|---|---|
| 21 cm/s 稳态速度 | 18.79 | **18.95** | +0.9% |
| 30 cm/s 稳态速度 | 27.23 | **26.67** | −2.1% |
| 检出失败率 | 0% | 0% | — |
| 速度噪声 | 较高 | 较低 | — |
| 换光照等级 | 要手改门限 | 自适应 | — |

**结论：后处理换掉，速度只变 ≤2%（在这两段接近匀速的参考录像上）。** 这有两层含义：

- 那 ~10% 的系统偏差**不来自**门限/平滑/窗口，而是几何（等效平面，见
  [`等效平面误差推导.md`](等效平面误差推导.md)）；
- 第二版的收益在**鲁棒性与可复现性**：不用逐档改常数、速度更平滑、失败率能自动统计。

> **一个例外要说清**：在更早那段 `truss_15s.mp4`（车在窗内并不匀速）上，
> 固定门限的全局拟合给 24.0，第二版的稳态窗给到约 26.8（未做平面修正），差 11%。
> 这不是阴影造成的，而是**估计方法 + 稳态窗选取**在非匀速段上的差异。
> 所以"两版差 ≤2%"只在匀速参考录像上成立；正式测量必须保证车在窗内匀速。

## 四、设计原则（从这次改进里总结）

1. **检测内核不动**：MOG2 是正式算法，不搞算法横评；
2. **改进全放后处理**：门限、门控、平滑、窗口、日志都能单独开关、单独回归；
3. **参数单一来源**：全部写进 `config.py`；
4. **换条件不换代码**：光照等级变，门限自适应；速度变，稳态窗自动选。

## 五、局限

- 亮度门限假设"目标是亮区"（白桁架），换深色目标要反过来；
- 强光把整幅画面推成前景时，算法层救不回来，只能改曝光/遮光；
- 平面修正依赖目标几何，换目标要重推。
