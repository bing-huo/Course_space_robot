# 算法对比与改进说明（v1 → v2）

> 对照对象：第一学期离线流水线（v1）与第二学期测速流程（v2）。
> 重点不在"换了什么检测器"，而在 **v2 的框架逻辑**：检测内核不变，改进全部发生在后处理。

## 一、两版各是什么

| | v1（第一学期） | v2（第二学期） |
|---|---|---|
| 输入 | 手机视频，离线读文件 | 工业相机（MVS SDK），可实时可离线 |
| 检测 | MOG2 + 形态学 + 面积阈值 | **同一套** MOG2 + 形态学 + 面积阈值 |
| 时间 | `len(h_t)/fps` 推算 | 硬件时间戳 + FrameClock（单调保护） |
| 标定 | 手点四角 180×60 | 棋盘板单应 H + 等效平面修正 |
| 速度 | 逐帧差分 + Alpha-Beta | Alpha-Beta + **自动稳态窗** |
| 阴影 | 未处理 | **自适应亮度门限** |
| 日志 | 无 | **逐帧检测日志**（失败率数据来源） |

## 二、v1 的框架

```
视频帧 → 灰度 → MOG2 → 形态学 → 最大轮廓(面积>阈值) → 质心
      → 四角透视 H → Alpha-Beta → 四阶段分类 → 报表
```

问题（都在第二学期被逐一处理）：

1. 时间基准靠帧数推算，丢帧就停表；
2. 区域尺寸硬编码；
3. 质心偏移是经验常数；
4. 标定要鼠标点四角；
5. 无逐帧日志，算不出失败率；
6. 阴影/强光没有任何处理。

## 三、v2 的框架（重点）

```
相机帧 ─► FrameClock(硬件时间戳)
       ─► 灰度
       ─► MOG2 前景 ──┐
       ─► 自适应亮度门限 ──► 前景 = 运动 ∧ 够亮
       ─► 形态学(开/闭)
       ─► 单目标门控(面积范围 + 离预测位置最近)
       ─► 轮廓质心(图像矩)
       ─► 单应 H（含等效平面修正 PLANE_SCALE）
       ─► Alpha-Beta(α=0.15, β=0.005)
       ─► 自动稳态窗(|v−v_target|/v_t ≤15% 且 ≥1.0 s)
       ─► 速度 / 轨迹 / 逐帧日志
```

### 3.1 自适应亮度门限（本版最关键的一块）

```
thr = 中位灰度 + 0.5 × (P95 − 中位)
前景像素 = (MOG2 == 255) 且 (灰度 ≥ thr)
```

- **为什么需要**：单侧强光把影子投得很黑，`detectShadows` 判不出来，影子会并进前景，
  质心被拖偏；同一段视频，无门限 18.0 cm/s，有门限 24.0 cm/s。
- **为什么不能写死常数**：固定 `gray≥100` 在 L0（更暗）会漏掉目标、在 L4（更亮）会放进背景光斑。
  用"画面自适应的分位数"就能随光照等级自动跟随。
- **代价**：目标本身如果很暗（比背景还暗），这个门限会把它滤掉——所以它适用于**亮目标+暗背景**，
  本项目正是这种（白色桁架/黑色背景）。

### 3.2 单目标门控（沿用调研结论，不是跟踪器）

三条规则：

1. 面积在 `[contourArea_min, ∞)`；
2. 质心落在测量区；
3. 多候选时取离上一帧预测位置最近的。

这就是"简单门控"，不引入 ByteTrack/DeepSORT。

### 3.3 Alpha-Beta 滤波

```
x_pred = x + v·dt
r = z − x_pred
x += α·r ;  v += (β/dt)·r
```

- 稳态参数 `α=0.15, β=0.005`：强抑噪；
- 为什么不用 Kalman：只有两个参数、物理意义直观，课程场景够用；
- 速度由滤波状态给出，不再用逐帧差分（差分噪声大，P90 比中位高 7%）。

### 3.4 自动稳态窗

```
|v(t) − v_target| / v_target ≤ 15%  且连续长度 ≥ 1.0 s
取最长连续段，段内速度取平均
```

- 避免把起步/驶出段算进平均；
- 判据直接来自 v2 测量协议 §5.1，不靠人工截取。

### 3.5 等效平面修正

标定板在桁架顶面，但俯视穿过镂空看到的白色结构以底部为主，等效平面比标定面低约 14 cm。
补偿系数 `PLANE_SCALE = (WD + 14) / WD = 1.1233`。推导见
[`等效平面误差推导.md`](等效平面误差推导.md)。

### 3.6 逐帧日志

每帧记录：帧号、时间、是否检出、面积、像素坐标、门限值。指标 2（检测失败率）直接由它统计。

## 四、对比结果（同一段录像，10 ms / F2.8 / 6 dB）

| 指标 | v1（逐帧差分、固定门限） | v2（αβ + 自适应门限） |
|---|---|---|
| 21 cm/s 稳态速度 | 18.79 | 18.95 |
| 30 cm/s 稳态速度 | 27.23 | 26.67 |
| 两段差异 | — | **<1.5%** |
| 检出失败率 | 0% | 0% |
| 速度噪声（P90/中位） | 较高 | 较低 |

**结论：算法改进没有改变那 ~10% 的系统偏差**——这恰好证明偏差不是算法造成的，
而是几何（等效平面）。算法改进的收益在**鲁棒性**：换光照等级不用改常数、速度更平滑、
失败率可自动统计。

加上等效平面修正后：

| 目标 | 修正后速度 | 误差 |
|---|---|---|
| 21 cm/s | 20.92 | −0.4% |
| 30 cm/s | 29.28 | −2.4% |

## 五、框架设计原则

1. **检测内核不动。** 遵循调研结论：MOG2 是唯一正式算法，不安排算法横评。
2. **改进全部放后处理。** 门限、门控、平滑、窗口、日志——每一块都能单独开关、单独回归。
3. **参数单一来源。** 曝光、面积阈值、αβ、平面修正都在 `config.py`。
4. **可复现。** 同一段录像跑两遍结果一致；逐帧日志可回放。
5. **失败可归因。** 日志里同时记录面积、门限、时间，失败帧能分成"没检出/面积不足/门限过滤"。

## 六、局限

- 依赖"背景固定 + 单目标"；多目标或背景变化时失效；
- 亮度门限假设目标是画面里的亮区（黑目标+白背景要反过来）；
- 强光把整幅画面推成前景时，MOG2 本身失效，算法层救不回来（只能改曝光/遮光）；
- 等效平面修正依赖目标几何，换目标/换高度要重推。
