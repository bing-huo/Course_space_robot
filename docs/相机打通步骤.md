## 步骤 2 · 准备 Python 绑定

MVS 安装目录下带着 Python 的接口库和官方样例，一般在：

```
<MVS 安装目录>\Development\Samples\Python\
├── MvImport\              # ← 需要的东西都在这
│   ├── MvCameraControl_class.py
│   ├── CameraParams_header.py
│   ├── MvErrorDefine_const.py
│   └── PixelType_header.py
└── GrabImage.py           # 官方取帧样例
```

**推荐做法**：把整个 `MvImport` 文件夹复制到仓库根目录下，与本项目的 `camera/` 平级。这样仓库自包含，换台电脑不用重新找路径。

### ⚠️ 这一步 90% 的坑都在这两个环境变量上

Python 能 `import` 到 `MvCameraControl_class`，但底层 `MvCameraControl.dll` 找不到，会报 `DLL load failed` 或 `找不到指定的模块`。原因是 MVS 的运行库不在系统 PATH 里。

`camera/backend.py` 里已经写好了自动处理，逻辑是：

```python
os.environ['MVCAM_SDK_PATH']      = str(MVS_PATH)
os.environ['MVCAM_COMMON_RUNENV'] = str(RUNTIME_DIR)
# Python 3.8+ 必须显式加 DLL 搜索目录
os.add_dll_directory(str(RUNTIME_DIR))
```

**`MVS_PATH` 怎么来**（代码里对应 `_resolve_mvs_path()`）：环境变量 `MVS_PATH` → 常见默认安装路径 → 在各盘符下 glob `Program Files/MVS*`、`MVS*`、`Hikrobot*`。
**`RUNTIME_DIR` 怎么来**（代码里对应 `_find_runtime_dir()`）：先在安装目录下试六种已知布局（`Runtime/Win64_x64`、`Runtime/x64`、`Development/Bin/x64` 等），**都不中就在安装目录里按最多 4 层深度搜 `MvCameraControl.dll`，以实际找到它的那个目录为准**。

> ⚠️ 不要照抄某个固定的 `Runtime\Win64_x64`。不同版本的 MVS 装出来的目录结构不一样——本机装在 `E:\MVS`，就没有 `Runtime\Win64_x64` 这一层。猜错不只是显示难看：这个目录还要同时喂给 `MVCAM_COMMON_RUNENV` 和 `os.add_dll_directory`，猜错就少一层保险。

想直接看探测结果：

```bash
python -m camera.camera_capture sdk
```

探测不到也不影响取帧（DLL 由系统 PATH 解决）；实在要固定下来，就设一个 `MVS_PATH` 环境变量，或在 `camera/backend.py` 顶部的 `MVS_PATH_CANDIDATES` 里加一行你机器上的实际路径。

**另外两条硬性要求**：Python 必须是 **64 位**（`python -c "import platform;print(platform.architecture())"` 应显示 `64bit`），MVS 也必须是 64 位版，两者要对上。

## 步骤 5.5 · 光学调校：对焦 / 光圈 / 曝光

**这一步不能省。** "能出图"和"图能用"是两回事——工业相机的成像质量由三件事决定，而且**顺序不能颠倒**：先对焦 → 再收光圈 → 最后定曝光。反过来的话，收光圈会改变景深，让"已经对准"失效；定曝光又会因为光圈变了而白定一次。

### 手动镜头没有实时画面就没法调

拍一张 → 存盘 → 打开 → 看，一轮好几秒，转对焦环的那一下根本看不到结果。所以用实时预览窗口：

```bash
python -m camera.camera_capture preview --zoom
```

窗口里按键：`q` 退出、`s` 存图、`a` 一键曝光、`z` 放大镜、`g` 三分网格、`+`/`-` 曝光 ×1.5 / ÷1.5、`]`/`[` 增益 ±1 dB。

### ① 先立对焦靶

对焦基准必须是**高对比的粗纹理**：打印一张棋盘格，或一张大号粗体字的纸。立在**工作距离 1.43 m** 处、画面正中。

> 白墙、天花板、远处家具这类**没有纹理**的东西不能当靶——锐度数值不会随对焦变化，等于在盲调。第一张实拍样张就是对着房间拍的、没有靶，所以从那张图上根本判断不出对焦状态是好是坏。

### ② 对焦要盯数字，不要只靠眼睛

HUD 里的 `SHARPNESS` 是**画面中心区域的 Laplacian 方差**，越大越锐（只取中心：靶子就在中央；把整幅算进去的话，背景纹理和传感器噪点会把真正想看的量稀释掉）。

光圈先开到 **F2.8**（通光最大、景深最浅，对焦最灵敏），然后慢慢转对焦环，让 `SHARPNESS` 到最大。**把离焦和合焦两边的数值都记下来**——这是对焦完成的客观凭据，比"看着挺清楚"立得住，汇报里也用得上。

### ③ 再把光圈收到 F4 ~ F5.6

对焦做完之后收光圈：景深变大，轻微的距离误差不会立刻糊掉。此时 `SHARPNESS` 会回落一点，**这是正常的，不要回去重新对焦**。

上界别超过 **F7 左右**。像元是 4.8 μm，F# 再大衍射斑就超过像元尺寸了，分辨率反被光学系统限制住——加光圈不会更清楚，只会更暗。

### ④ 最后定曝光并锁死

按 `a` 一键曝光，让相机自动定一次曝光与增益，代码随后会立刻把它锁回 `Off`。

**实验采集绝不能用自动曝光。** 它会随光照自己变，把"光照"和"相机调整"两个变量混在一起——这正是上学期手机方案的毛病。一键曝光只是借相机的自动功能快速拿到一个合理起点，之后所有采集一律走手动值。

**顺手把过曝边界也试出来**：按 `+` 逐档加曝光，直到 HUD 里 `过曝(>250)` 的占比明显抬头，记住那个曝光值。它就是这颗相机的动态上限，抗强光实验的余量从这里算。

### 做完记下这四项

| 记什么 | 为什么 |
|---|---|
| 合焦 / 离焦的 SHARPNESS | 对焦做完的凭据 |
| 最终光圈值（F#） | 复现条件，要写进采集协议 |
| 最终曝光 / 增益 | 复现条件，要写进采集协议 |
| 开始出现过曝的曝光值 | 动态余量的上界 |

## 步骤 6 · 跑 bench：把三项待确认一次做实

```bash
python -m camera.camera_capture bench --seconds 60
```

这个命令做四件事，输出一段可直接抄进文档的报告：

**① 实测帧率。** 规格书的 201.4 fps 是极限值，实测值才是能写进报告的。它同时决定 §5.4 的工程约束余量。

**② 硬件时间戳的单位自证。** 做法很取巧：读相邻两帧的设备时间戳差值，与已知的帧间隔对比。若实测 200 fps（帧间隔 5 ms），而时间戳差值是 `5,000,000`，那单位就是纳秒；是 `5,000` 就是微秒。**这样不需要查手册就能确定单位**，也顺便验证了时间戳是否单调递增。

**③ FrameID 连续性。** 统计帧号的跳变次数。**如果有跳变，说明采集过程中真的丢帧了** —— 这是判断"丢帧"唯一的硬证据，也是 `detect_log.csv` 需要的字段。P0.3.a 的时间基准重构就靠它兜底。

**④ 5 分钟不掉线。** 用 `--seconds 300` 跑满 5 分钟。这就是 P1.2 的验收判据。

**跑完把四个结果回填到 `docs/相机与镜头参数汇总.md` §6 的待确认表**（第 1、2、5 三项），状态从 ⬜ 改 ✅。

## 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `DLL load failed` / 找不到指定模块 | MVS 运行库不在 DLL 搜索路径 | 见步骤 2：设两个环境变量 + `os.add_dll_directory`，并确认 Python 是 64 位 |
| `MV_CC_EnumDevices` 返回 0 个设备 | 线缆/USB 口/驱动 | 换主板原生 USB 3.0 口、不接 HUB、换线；先在 MVS 客户端里确认能看到 |
| 枚举得到但打不开设备 | 权限模式冲突 | MVS 客户端还占着相机，**先关掉客户端** |
| 出图全黑 | 曝光过短 / 镜头盖没摘 / 光圈全关 | 用 `info` 看曝光值，先设 10 ms 试；检查镜头光圈环 |
| 出图偏暗**且**发虚 | 光圈接近全关 + 对焦没做 | 见步骤 5.5：光圈开 F2.8、立靶、按 `SHARPNESS` 对焦。**别靠调曝光去救模糊**，这是两码事 |
| 转了对焦环，锐度数字不动 | 画面里没有对焦靶 | 立一张棋盘格或粗体字纸在 1.43 m 处；白墙、天花板不算靶 |
| 出图全白 / 一片雪花 | 像素格式转换不对 | 彩色款必须是 Bayer GB → BGR8 的转换；确认 `info` 里的像素格式 |
| 帧率远低于预期（只有 30 左右） | 掉到 USB 2.0 了 | 换 USB 3.0 口和认证线；`bench` 会报实际带宽 |
| 跑一会儿就掉线 | USB 供电不足 | 别接无源 HUB；换短一点的认证线 |
| 报 `MV_CC_PIXEL_CONVERT_PARAM_EX` 不存在 | SDK 版本差异 | 改 `camera/backend.py` 里的 `_PIXEL_CONVERT_PARAM` 别名，用不带 `_EX` 的结构体 |
| 报 `MV_CC_Initialize` 不存在 | 旧版 SDK 无此函数 | 代码里已用 try 包住；忽略即可 |
