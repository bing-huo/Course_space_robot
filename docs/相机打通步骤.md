## 步骤 2 · 准备 Python 绑定

MVS 安装目录下带着 Python 的接口库和官方样例，一般在：

```
<MVS 安装目录>\Development\Samples\Python\
├── MvImport\              # ← 需要的东西都在这
│   ├── MvCameraControl_class.py
│   ├── CameraParams_header.py
│   ├── MvErrorDefine_const.py
│   └── PixelType_header.py
└── GrabImage.py           # 官方取帧样例
```

**推荐做法**：把整个 `MvImport` 文件夹复制到仓库根目录下，与本项目的 `camera/` 平级。这样仓库自包含，换台电脑不用重新找路径。

### ⚠️ 这一步 90% 的坑都在这两个环境变量上

Python 能 `import` 到 `MvCameraControl_class`，但底层 `MvCameraControl.dll` 找不到，会报 `DLL load failed` 或 `找不到指定的模块`。原因是 MVS 的运行库不在系统 PATH 里。

`camera/backend.py` 里已经写好了自动处理，逻辑是：

```python
os.environ['MVCAM_SDK_PATH']      = str(MVS_PATH)
os.environ['MVCAM_COMMON_RUNENV'] = str(MVS_PATH / 'Runtime' / 'Win64_x64')
# Python 3.8+ 必须显式加 DLL 搜索目录
os.add_dll_directory(str(MVS_PATH / 'Runtime' / 'Win64_x64'))
```

`MVS_PATH` 按优先级自动探测：环境变量 `MVS_PATH` → 默认安装路径 → 仓库根下的 `MvImport` 同级目录。探测不到就在 `camera/backend.py` 顶部的 `MVS_PATH_CANDIDATES` 里加一行你机器上的实际路径。

**另外两条硬性要求**：Python 必须是 **64 位**（`python -c "import platform;print(platform.architecture())"` 应显示 `64bit`），MVS 也必须是 64 位版，两者要对上。

## 步骤 4 · 读能力参数

```bash
python -m camera.camera_capture info
```

会打印：像素格式、当前分辨率、曝光时间范围、增益范围、触发模式、payload 大小等。

**要核对的两件事**：

- 曝光范围应是 **9 μs ~ 10 s**，增益 **0 ~ 16 dB**（与规格书对得上）；
- 当前像素格式是不是 **Bayer GB8**（彩色款应有）。如果是 `Mono8`，说明拿到了黑白款，需要回去核对型号。

## 步骤 6 · 跑 bench：把三项待确认一次做实

```bash
python -m camera.camera_capture bench --seconds 60
```

这个命令做四件事，输出一段可直接抄进文档的报告：

**① 实测帧率。** 规格书的 201.4 fps 是极限值，实测值才是能写进报告的。它同时决定 §5.4 的工程约束余量。

**② 硬件时间戳的单位自证。** 做法很取巧：读相邻两帧的设备时间戳差值，与已知的帧间隔对比。若实测 200 fps（帧间隔 5 ms），而时间戳差值是 `5,000,000`，那单位就是纳秒；是 `5,000` 就是微秒。**这样不需要查手册就能确定单位**，也顺便验证了时间戳是否单调递增。

**③ FrameID 连续性。** 统计帧号的跳变次数。**如果有跳变，说明采集过程中真的丢帧了** —— 这是判断"丢帧"唯一的硬证据，也是 `detect_log.csv` 需要的字段。P0.3.a 的时间基准重构就靠它兜底。

**④ 5 分钟不掉线。** 用 `--seconds 300` 跑满 5 分钟。这就是 P1.2 的验收判据。

**跑完把四个结果回填到 `docs/相机与镜头参数汇总.md` §6 的待确认表**（第 1、2、5 三项），状态从 ⬜ 改 ✅。

## 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `DLL load failed` / 找不到指定模块 | MVS 运行库不在 DLL 搜索路径 | 见步骤 2：设两个环境变量 + `os.add_dll_directory`，并确认 Python 是 64 位 |
| `MV_CC_EnumDevices` 返回 0 个设备 | 线缆/USB 口/驱动 | 换主板原生 USB 3.0 口、不接 HUB、换线；先在 MVS 客户端里确认能看到 |
| 枚举得到但打不开设备 | 权限模式冲突 | MVS 客户端还占着相机，**先关掉客户端** |
| 出图全黑 | 曝光过短 / 镜头盖没摘 / 光圈全关 | 用 `info` 看曝光值，先设 10 ms 试；检查镜头光圈环 |
| 出图全白 / 一片雪花 | 像素格式转换不对 | 彩色款必须是 Bayer GB → BGR8 的转换；确认 `info` 里的像素格式 |
| 帧率远低于预期（只有 30 左右） | 掉到 USB 2.0 了 | 换 USB 3.0 口和认证线；`bench` 会报实际带宽 |
| 跑一会儿就掉线 | USB 供电不足 | 别接无源 HUB；换短一点的认证线 |
| 报 `MV_CC_PIXEL_CONVERT_PARAM_EX` 不存在 | SDK 版本差异 | 改 `camera/backend.py` 里的 `_PIXEL_CONVERT_PARAM` 别名，用不带 `_EX` 的结构体 |
| 报 `MV_CC_Initialize` 不存在 | 旧版 SDK 无此函数 | 代码里已用 try 包住；忽略即可 |
