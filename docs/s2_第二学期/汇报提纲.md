## 一、上学期回顾

**做到了什么**：一套运动捕获视觉评测系统——MOG2 背景差分提取目标（替代初代 YOLOv5 方案，快 10 倍以上）→ 形态学去噪 + ROI 遮罩 → 图像矩计算质心 → 四角透视标定完成像素到厘米的换算 → 自研 Alpha-Beta 自适应滤波器 → 四阶段运动状态分类，并自动生成学术报表。已在 21 cm/s 与 31 cm/s 两种速度下完成评测。

**三条不足，正好对应本学期的三个升级**：

- **采集端不可控**：手机拍摄后离线处理。曝光和白平衡是自动的、会随光照自己变，帧率也是固定的。测出来的误差里混着"相机自己做的调整"，说不清来源。
- **场地不规范**：尺寸是临时划定的，地面材质、边界对比度都没有控制，标定也缺少统一的精度验证。换个人、换一天，结论不一定能复现。
- **光照不可复现**：只利用了室内自然光，没有分级、没有记录、也没法重放——而模拟太空环境恰恰要求光照是一个能设定、能复现的自变量。

## 二、本学期任务：两条主线

**一句话目标**：把"强光条件下还能不能把速度测准"做成一个可复现的实验。两项指标——强光下稳态速度相对误差 ≤ 20%，检测失败率 ≤ 15%。

**主线 A · 算法移植重调**：把上学期已经跑通的算法搬到新硬件上，重新标定。这不只是"换个输入源"——时间基准要重构（原来的时间靠帧数推算，一旦丢帧就会停表，速度直接算错），标定尺度要重做，检测参数要按新的尺度重算。

**主线 B · 算法升级优化**：抗强光 + 实时化。核心判断是**抗强光先靠曝光、再靠算法**——目标一旦过曝饱和，在图像里就和背景没有差别了，算法救不回来；所以先把曝光控制住，算法只负责处理残余。

## 三、现有进展

### 3.1 硬件到位与装配

| | 型号 | 关键参数 |
|---|---|---|
| 相机 | 海康 MV-CU013-A0UC | 全局快门、4.8 μm 像元、1/2" 靶面、1280 × 1024、最高 201.4 fps |
| 镜头 | 海康 MVL-HF0828M-6MPE | 8 mm 定焦、F2.8 ~ F16 手动光圈、手动聚焦 |

两者都是 C-Mount、法兰后焦同为 17.526 mm，**直接安装，不需要转接环**。

有两点值得单独说：**全局快门**保证运动中的目标不会被拉伸变形；**手动曝光 + 手动光圈**意味着"光照"这个变量第一次可以被单独控制住——后面的分级光照全部建立在这个前提上。

### 3.2 接入链路打通

相机走的是 USB3 Vision / GenICam 协议，**不是 UVC**，常规的 `cv2.VideoCapture` 打不开它，必须通过海康 MVS SDK 接入。链路分四层，逐层打通并各自留有验证记录：

| | 层 | 验证方式 |
|---|---|---|
| ① | 硬件接入 —— USB 3.0 直连主机，设备正常枚举 | 终端设备枚举输出 / 客户端设备树 |
| ② | MVS SDK —— 海康官方驱动与运行库 | SDK 定位输出 + 客户端连续出图 |
| ③ | Python 绑定 —— 接口库接入项目，可枚举设备读参数 | 终端读出相机能力寄存器 |
| ④ | 应用层 —— 逐帧取图、硬件时间戳、FrameID | 实拍样张 + 逐帧时间信息 |

### 3.3 实测验证

不照抄手册，而是把相机读上来核对：

- 曝光范围实测 **9 μs ~ 10.0 s**、增益 **0 ~ 16.37 dB**、像素格式 **Bayer GB8**，三项与规格书完全吻合，说明读到的是真实能力值；
- 实拍样张 **1280 × 1024**，彩色还原正常；
- **硬件时间戳与 FrameID 逐帧可读** —— 这一条决定了主线 A 里的时间基准可以走相机硬件时钟，精度比软件计时高一档。

另外把**光学参数**也做实了：对焦不看"感觉清楚了"，而是用画面中心区域的 **Laplacian 方差**当客观判据——转对焦环时盯这个数字找最大值，合焦与离焦两侧的读数都留了记录。光圈、曝光的最终值一并记入采集协议。这一步的意义是让"光照"成为唯一还在变的量。

### 3.4 接入过程中解决的两次卡点

根因是同一类：海康 SDK 里带 `Ex` 后缀的结构体，必须配同名的 `Ex` 函数。混用不会报类型错误，只会给一个参数错误码，或者一串看着像天文数字的乱码（比如分辨率读成 `1280 × 2³²`）。排查路径是**从异常数值反推字节布局**，定位到结构体错位。

> 可选讲，30 秒。体现的是能独立处理厂商 SDK 的边界问题。
