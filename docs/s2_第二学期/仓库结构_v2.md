## 一、为什么要动

第一学期所有代码都堆在 `CV/` 一个目录里：主程序、教学版、标定工具、旧权重、素材、输出结果混在一起。第二学期要新增五块互相独立的东西——**相机接入、标定、光源、实时可视化、统计分析**——再往 `CV/` 里塞就会变成第二个垃圾堆，而且"哪份代码跑在哪个阶段"会说不清。

同时 P0.3 要求把参数外置、把素材归档，这两件事都需要先有一个明确的目录约定。

## 三、三条设计原则

### 1. `CV/` 冻结，不拆不搬

**理由有三条，都是为了不把汇报和回归测试搞砸：**

- 未来一两周内，`CV/` 是唯一能跑的代码。动它有风险，收益却只是"看起来更整齐"。
- P0.3 的总验收是**回归测试**——用 `data/v1_baseline/` 的两段视频跑新版，要求与 v1 输出的稳态速度误差差异 **< 2 个百分点**。v1 必须保持在能跑、能复现的状态，否则没有对照。
- `CV/step1_calibrate.py` 与 `CV/calibration_config.json` 之间有路径依赖，搬动容易踩坑，而它们最近就会被新标定流程取代。

**什么时候再收进 `v1/`**：P0.3 整顿完成、回归测试通过之后。那时候 `CV/` 可以整体改名 `v1/`，一步到位，而且有回归测试兜底。

### 2. 先加后移（additive-first）

本次迁移只做**必要的移动**，其余全部是新建：

| 动作 | 对象 | 依据 |
|---|---|---|
| **移动** | `CV/test_video_21.mp4` → `data/v1_baseline/` | P0.3.g 明确要求 |
| **移动** | `CV/test_video_31.mp4` → `data/v1_baseline/` | 同上 |
| 新建 | `config.py`、`camera/`、`data/` 等 | 本文件第二节 |
| 不动 | `CV/` 其余全部 | 见原则 1 |

移动用 `git mv`，保留历史，且随时可 `git reset` 回滚。

### 3. 数据与代码分离

`data/` 只放数据和产物，不放代码；代码只从 `config.py` 读路径，不写死相对路径。这样：
- 换场地、换区域尺寸只需改 `config.py`（P0.3.c）；
- 素材被新版本代码污染的风险消失（P0.3.g）；
- `data/` 将来可以整体排除出版本库。

## 五、本次不做的事（以及为什么）

| 不做 | 为什么 |
|---|---|
| 把 `CV/main.py` 改名 `main_v2.py` 并原地改造 | P0.3 要求"重构不改变物理结论"，原地改就永远说不清是哪一步改坏的。第二学期主程序应当是**新建**的 `main_v2.py`，与 v1 并存到回归测试通过为止 |
| 把 `calibration_config.json` 搬到 `calibration/` | 会切断 `CV/step1_calibrate.py` 的路径依赖。新标定模块自己读 `config.py` 里的路径，两边并存一段 |
| 给 `docs/` 里的 PDF 改名 | 规格书文件名带日期和批次号，是溯源凭据，保持原样 |
| 处理 `.obsidian/` | 仓库同时是个 Obsidian 库（`docs/` 里的 `[[双链]]` 依赖它），保留。**注意**：它会把 `docs/` 下的 PDF 也纳入索引，与本项目本身无关 |

## 六、执行方式

> ⚠️ **以下命令都在仓库根目录下执行**，先 `cd` 进去：
>
> ```powershell
> cd "C:\Users\binghuo\Desktop\科创课\Course_space_robot"
> ```
>
> 本项目所有代码都用 `import config` 读根目录的全局参数，从别处运行会直接报
> `ModuleNotFoundError`。`python -m camera.*` 系列也一样。

```bash
# 1. 先看要做什么，不动文件
python tools/migrate_repo.py

# 2. 确认无误后执行
python tools/migrate_repo.py --apply

# 3. 出问题就整体回滚
git reset --hard HEAD
```

脚本默认 dry-run，只打印将要执行的 `git mv` 命令。它**不会删除任何文件**，只做移动和创建空目录占位。
