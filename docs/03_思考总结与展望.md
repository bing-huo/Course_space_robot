# 思考总结与展望

> 记录第二学期做对了什么、走了哪些弯路、沉淀了哪些方法，以及对第三学期的建议。
> 结合 `codex/second-semester-plan` 分支上 2026-10-13 那版《第二学期项目实施方针》的收敛过程。

---

## 一、做对了什么

1. **先物理，后算法。** 抗强光的第一步是把曝光压回线性区，而不是写更多阈值逻辑。
   实测也证明：目标一饱和，任何掩码都救不回来。
2. **参数单一来源。** 所有会影响物理结论的数字只放在 `config.py`，改参数不碰主流程，
   换机位只改一处。
3. **实测覆盖设计值。** 文档里的 WD、px/cm、曝光、轮廓阈值都标注了实测日期；
   没测的写"待测"，不拿估算值冒充结果。
4. **先定几何，再买设备。** 镜头选型由区域尺寸反推，支架高度由镜头反推——顺序对了，
   买错的风险就小。
5. **刹车线。** "L0 失败率不达标就不进 P4"，避免带着坏基线去做强光实验，
   最后分不清是强光的问题还是本来就有的问题。
6. **放弃深度学习做主检测。** 背景固定、单目标、无类别需求，MOG2 又快又稳；
   YOLO 只保留为对照。这是任务边界决定的取舍。
7. **版本库与文档同步。** 每个关键节点都提交并推送，机位参数、实测结论、工作点都能追溯。

## 二、走过的弯路

| 弯路 | 代价 | 教训 |
|---|---|---|
| 按 100×70 cm 区域设计（需 1.43 m 机位），实际机位只有 120 cm | 区域缩到 78×60、稳态窗从 2.0 s 降到 1.39 s，多轮文档返工 | **先量机位再定区域**，不要反过来 |
| 先买灯、后测频闪 | 发现光源是 100 Hz 纹波，2~5 ms 曝光全废，工作点被迫改成 10 ms | 买灯前先确认**调光方式**，到货当天就测频闪 |
| 硬件时间戳单位没先确认 | 差点按 1 ns 算，速度会差 10 倍且不报错 | 新设备先做"单位自证"（用已知帧率反推刻度） |
| 录制命令 `writer.write(frame)` 传错对象 | 一录就崩，白等一轮 | 设备链路要**端到端**跑通一次，不能只测取帧 |
| 几何数字散落在 README、相机文档、规划、周计划里 | 同一参数出现 100×70 / 90×70 / 78×60 三种口径 | 物理参数只留一处，其余文档引用它 |
| 文档直接改写历史结论 | 前后版本对不上 | 采用"顶部加实测覆盖横幅 + 保留旧段作决策记录"的方式 |

## 三、方法沉淀（可直接复用）

1. **任何"设计值"都要有一条停止条件**：什么时候算错、怎么发现、发现后怎么改。
2. **每个参数问三个问题**：谁测的？什么条件下测的？变了要重测什么？
3. **先跑通最窄的闭环**：取帧 → 检测 → 质心 → 速度，再逐步加光照、加标定；
   不要一开始就搭完整流水线。
4. **判据要能写成一句可执行的话**："轻敲画面位移 <3 px"、"100 帧极差 <2 灰度级"、
   "尺度相对误差 ≤1.5%"，而不是"效果良好"。
5. **把不可控因素变成记录项**：环境光、灯温、曝光、机位，能记就记；
   记不了的要明确写"未控制"。
6. **给下一个接手的人留"反悔点"**：哪些改动会让数据作废、怎么回滚。

## 四、codex 分支的收敛过程（值得保留的思考）

10 月 13 日那版《第二学期项目实施方针》把方案从"龙门架 + 多灯 + 算法横向对照"
收敛到"三脚架 + 两盏灯 + 单一算法主线"，核心是几条本科课程适用的原则：

- **任务闭环优先**：先完成"场地 → 成像 → 标定 → 检测 → 测速 → 实验 → 汇报"整条链，
  再谈优化；
- **用满足需求的最简单方案**：固定相机、干净背景、单一目标，不引入深度学习和多目标跟踪；
- **先解决物理成像，再调算法**：曝光、增益、光圈、灯位、反射、频闪，按这个顺序排查；
- **继承上学期有效成果**：MOG2、质心、单应、Alpha-Beta 都沿用，不另起炉灶；
- **不做算法横向评测**：本项目的自变量是光照，不是算法类别；横向对比只会增加工作量；
- **未实测的内容必须标成方案/预计值**。

这套取舍和后来的实测结论是一致的：**方案越简单，变量越少，结论越站得住。**
现在回头看，唯一的偏差是"灯"——当时假设有调光，实际买的是无调光工作灯，
导致了频闪和等级分级的返工。

## 五、对第三学期的建议

1. **把跟踪点做成物理标记。** 车顶贴哑光白/棋盘标，标定板垫到同一高度。
   这一步同时解决：黑布下的对比度、视差误差、`CY_OFFSET_K` 依赖经验值三个问题。
2. **并入捕获段要换机位。** 同画面看"测量段 + 抓取段"需要 ≈140×90 cm 区域，
   WD 会到 1.9 m 左右；**换机位 = 全部标定作废**，必须留到学期之间做，
   不要在学期中间动。
3. **数据一次性采全。** 每段同时存原始视频、逐帧日志、条件表，
   后期换算法不用重拍。
4. **代码先分层。** `main_v2` 拆成"帧源 / 检测 / 标定 / 估计 / 输出"五块，
   换相机只动帧源，换算法只动检测。
5. **别把课程做成竞赛。** 指标只有两个，够用就好；把时间花在标定和数据质量上，
   比多写一个算法模块回报高。

## 六、一句话总结

> 这个项目真正的难点不在算法，而在**把不可控的物理条件变成可控、可复现、可追溯的变量**。
> 相机参数、灯位、机位、时间基准——每一项都直接进入最终误差，而且比代码更难改。
> 第二学期最大的收获，是学会先问"这个数是怎么来的、变了会怎样"，再写代码。
